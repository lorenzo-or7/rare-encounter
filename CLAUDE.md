## Hard rules
- Implement the requested phase ONLY. Phase 00 is the first authorized phase.
- Do not change approved functionality, typography, identity, motion or scope without authorization.
- Never infer successful tests from an implementation. Execute and report checks accurately.
- Use React + TypeScript + Vite, strict typing, modular design and React-independent matching logic.
- Avoid generic AI-looking UI, random gradients, excessive glass/neon, redundant effects and boilerplate copy.
- Preserve original approved React Bits components, and verify actual installed code/skill availability before use.
- Motion for React for state/layout/gestures, CSS for lightweight details; respect reduced-motion.
- Public GitHub; All Rights Reserved; branch per phase. Do not merge, deploy or push without authorization.
- Never ship the rejected landscape animation/video pack.
- Pokémon/TCG assets require rights review before public release.

## Installed skills and token discipline
- Inspect available skills ONCE per new phase/task. Do not claim any skill is installed without verifying.
- Use relevant installed skill(s) selectively: frontend-design for major UI; quality/a11y skills for audits; Humanizer for final copy. Avoid invoking all skills for every task.
- UI UX Pro Max, Taste Skill, Impeccable, Web Design Guidelines and Humanizer also serve as editorial principles if matching executable skills are unavailable.
- Prefer targeted file reads/searches, brief responses, summarized command output, no giant diffs or redundant reports.
- Never use parallel agent swarms or Ruflo unless necessary, available, and approved.
- For uncertain requirements, note the blocker; do not replace the decision.

## Phase gate
